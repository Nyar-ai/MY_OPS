# 架构决策记录（ADR）

> 本文件集中记录 MY_OPS 全局位姿模块的关键决策：背景、决定、理由、后果、验证方式。
> 之所以集中在一个文件而非每决策一个文件，是因为这些决策彼此强耦合
> （例如 ADR-0006 的阈值直接由 ADR-0007 的零偏上限决定），集中阅读才能看清约束链。

---

## ADR-0001：融合架构 —— 分解式（陀螺管航向 / 双轮管位移），不引入卡尔曼滤波

**背景**：可用传感器只有两只定向轮（脉冲+方向）与一只单轴陀螺（CY-Z），MCU 为 72MHz 无 FPU 的 F103C8，RAM 20KB。

**决定**：航向完全由陀螺提供（速率积分 + 绝对角慢校正），位置完全由双轮里程提供（中点法旋转）；两者之间只有"用当前航向旋转位移"这一条耦合。

**理由**：
- 双轮系统对航向的观测能力天然很弱（两轮只测两个正交方向的平移），用它们去修正陀螺只会引入机械误差；
- 陀螺对位移毫无观测能力，融合无意义；
- 分解后每一部分都能在 PC 上独立单测，误差可归因（航向误差 vs 里程标定误差），便于现场定位问题；
- 卡尔曼滤波需要噪声模型、矩阵运算与调试成本，收益在"陀螺足够准、轮子标定足够准"的前提下接近零。

**后果**：位置精度上限由"每米脉冲标定"决定（见运行说明 §6.2），航向精度上限由陀螺决定。

**验证**：单测 T4（几何）、T7（航向）、T8（零偏）分别独立覆盖三条链路。

## ADR-0002：在 App 层补 `CC1S=01` 修复编码器计数（不改 `tim.c`、不用 DMA）

**背景**：CubeMX 为 TIM1/TIM2 生成的是"外部时钟模式 1 + TI1FP1 触发"（`SlaveMode=TIM_SLAVEMODE_EXTERNAL1`，`InputTrigger=TIM_TS_TI1FP1`），只调用了 `HAL_TIM_SlaveConfigSynchro()`。

**实测结论**：该 HAL 函数最终只走到 `TIM_SlaveTimer_SetConfig()`，**只写 SMCR（TS+SMS）**，完全不碰 `CCMR1`。而 RM0008 明确要求外部时钟模式 1 必须 `CC1S=01` 才能把 TI1FP1 接入从模式控制器。**缺少这一步，计数器一个脉冲都数不到。**

**决定**：不改 `tim.c`（避免与 CubeMX 重新生成冲突），而是在 `Ops_Hw_Init()` 里用
`HAL_TIM_IC_ConfigChannel(&htim1, {ICSelection=TIM_ICSELECTION_DIRECTTI, ICFilter=OPS_ENC_IC_FILTER}, TIM_CHANNEL_1)`
补上 `CC1S=01` 并配置输入滤波，然后 `HAL_TIM_Base_Start()` 使能计数（而非 `HAL_TIM_Encoder_Start`——那不是外部时钟模式）。

**理由**：`TIM_TI1_SetConfig()` 会写 `tmpccmr1 |= TIM_ICSelection`（即 `CC1S_0=0x1`）、`IC1F`、并清 `CC1E`（正好不需要捕获中断）；把修复放在 App 层可以同时解决 `TriggerFilter=0` 的滤波缺失问题。

**后果**：滤波用 `OPS_ENC_IC_FILTER=0x8`（fDTS/8 取 6 样 ≈0.67us），对真实脉冲（3m/s 极限下脉宽 ≥12us）无衰减。

**验证**：单测 T5 覆盖读-差-存的无损性；硬件上通过 DEBUG 帧的 `cnt_a/cnt_b` 观察计数。

## ADR-0003：编码器一律"读-差-存"，永不写 `CNT`

**背景**：本模块会在运行时擦写 Flash（零偏落盘），F1 的页擦除会让 CPU 停摆 20~40ms，期间 1ms 任务与所有中断都被推迟。

**决定**：采样层只读 `TIMx->CNT` 并与上次值做**有符号 16 位差**，把差值当作增量累加；绝不调用 `SET_COUNTER(0)` 或清零计数器。

**理由**：
- 计数器由硬件在暂停期间继续计数，读-差-存是天然的"无损"方案；
- 写 `CNT` 不仅会丢脉冲，还会与"读取"形成竞争。

**后果**：调度抖动、任务延迟、Flash 停摆都不影响里程精度（只影响速度的分母，而分母用实测毫秒数）。

**验证**：单测 T5.5 模拟 40ms 停摆 + 400 个脉冲，增量完全正确；T5.3/T5.4 覆盖正/反向 16 位回绕。

## ADR-0004：CY-Z 侧"零未文档化命令" + 模式自动判定 + 帧周期自适应

**背景与事实核查**（直接依据官方资料，不是推测）：
- 官方《CY-Z协议.md》的命令表只有 `0x01`（角度清零/零偏校准）、`0x04`（查询）、`0x05/0x06/0x07`（比例校准）、`0x08`（读比例因子），**没有"设置上报速率"命令**；
- SDK 头文件里有 `CYZ_RATE_50_HZ/20_HZ/10_HZ/QUERY` 与 `CYZ_CMD_SET_RATE=0x03`，但文档未定义、示例也未使用；
- 官方 f103 示例 `main.c` 启动只发 `CYZ_ZeroAngle()`，并注释"不会改变模块的上报速率"。

**决定**：**不发送任何未文档化命令**。上电先被动监听 300ms：
收到遥测 → 推流模式（不再发查询）；无帧 → 查询模式（100Hz 发 `0x04`，连续无响应自动退避到 20Hz）。
同时运行期测量帧周期，把丢帧超时设为 `3 × 实测周期`（钳位 25~300ms）。

**理由**：原计划"发命令设为 200Hz"在官方文档中不存在，属于对模块固件行为的假设；
一旦模块忽略该命令，200Hz 假设会导致超时阈值过紧、频繁误判丢帧。自适应方案对 10/20/50Hz 甚至未来速率都成立。

**后果**：上报给底盘的 100Hz 与陀螺实际速率解耦；INFO 帧暴露 `gyro_period_ms` 与 `cyz_mode` 供现场核对。

**验证**：单测 T2（协议层，含官方样例帧 CRC=0x072A）与 T5.7/T5.8（50Hz→60ms、200Hz→25ms 的超时自适应）。

## ADR-0005：航向 = 速率积分（零阶保持） + 每帧绝对角慢校正（α=0.05）

**背景**：最初设计是"对 `AngleDeg` 的逐帧增量按 tick 线性插值分配"。50Hz 下每帧间隔 20ms。

**量化分析**：插值必然引入约半个到一整个帧周期的滞后。在"边转边走"（弧线）时，
滞后 δθ 会把每步位移转错方向，误差按 `位移 × δθ` 累积：以 0.5m 的 90° 圆弧、180°/s、20ms 帧周期估算，
系统误差约 **8mm**，属于 25mm 预算的显著占比，且随工况不可预测。

**决定**：改用速率积分 `yaw += (GyroDps − bias) · dt`（零阶保持，**在匀速旋转下不引入任何额外滞后**），
并每收到一帧遥测做一次慢校正：`yaw += wrap180(AngleDeg − (yaw + K)) · 0.05`
（K 为"我们归零时解出的恒定偏置"，ZERO 时与检测到模块重定基时重解）。

**理由**：速率积分在匀速工况（原地转向、匀速弧线）下无滞后；慢校正负责约束长期漂移与比例误差，
其引入的滞后 ≈ `α/(1−α) × 帧周期` ≈ 1ms，可忽略。α=0.05 @50Hz ≈ 0.4s 时间常数。

**后果与敏感性**：稳态航向误差 ≈ `(比例误差 × ω × T_frame) / α`。
1% 比例误差 @90°/s → 0.36°；5% 比例误差 → 1.8°。因此**比例校准（官方 0x05/0x06）值得做**。

**验证**：单测 T7.1（±0.3°）、T7.2（1% 比例误差下 <1.5°）、T7.3（原地旋转位置恒为 0）。

## ADR-0006：ZUPT 用"100ms 滑窗 + 8 脉冲"判据，静止期间**冻结位置与航向**

**背景**：最初设计是"单轮 ≥2 脉冲/ms 视为运动"。2 脉冲/ms = **0.356 m/s** ——
这意味着低于 0.356 m/s 的慢速爬行会被判为静止并**冻结位置**，是致命缺陷
（最低工况 0.1 m/s 会被完全吞掉）。

**决定**：改用 100ms 滑窗：窗口内"两轮 |脉冲| 之和 ≥ 8"即视为运动（8 脉冲/100ms ≈ **0.014 m/s**，
远低于最低工况、又高于计数噪声底），并结合角速度峰值判据（见 ADR-0007）。
连续静止累计 ≥200ms 后置 `static`，此时**丢弃亚阈值脉冲并冻结航向**。

**理由**：
- 阈值必须落在"真实最慢运动"与"±1 计数量化噪声"之间，单看 1ms 无法两全，滑窗可以；
- 冻结航向是达成"静止 ≤1°/min"的关键：残余零偏造成的角度漂移在静止时被直接丢弃，而不是靠滤波器慢慢压。

**后果**：静止检出有 200~300ms 延迟（可接受）；静止期间亚阈值真实运动（<0.014 m/s）会被忽略（非工况）。

**验证**：单测 T6.2（亚阈值脉冲下位置恒为 0）、T6.3（真实运动一个窗口内解除）、T8.1（静止期间 yaw 完全冻结）。

## ADR-0007：静止角速度阈值必须大于最坏残余零偏；并用"残差稳定带"兜底

**背景**：零偏自愈的判据是"静止时陀螺残差 → 修正 bias"。但如果
`ZUPT_GYRO_DPS`（静止阈值）小于实际残余零偏，则陀螺永远显示"在动" ⇒
永远判不出静止 ⇒ **永远学不到零偏**（先有鸡还是先有蛋）。原设计阈值 0.3°/s 就踩了这个陷阱。

**决定**：
1. `OPS_ZUPT_GYRO_DPS = 0.6f`（=36°/min，远低于任何真实机动，又高于典型校准后残余零偏）；
2. 增加"残差稳定带"兜底：当轮子静止、窗口内角速度**极差 < 0.05°/s**、且峰值 ≤ 单次修正上限 1°/s 时，
   也允许进入零偏估计（一个真实旋转不会是"完全恒定的常值"）。

**理由**：把"是否允许估计零偏"与"是否冻结位置/航向"**解耦**为两个标志
（`s_bias_ok` 与 `s_static`）：即使零偏大到触发了兜底逻辑，也绝不影响运动判据与积分行为，
最坏情况只是零偏估计被污染，不会让系统失去运动感知。

**后果**：`OPS_ZUPT_GYRO_DPS` 与 `OPS_BIAS_LIMIT_DPS` 之间存在约束 `阈值 < 上限`，已在代码注释中写明。

**验证**：单测 T8.1 用 0.4°/s 残余零偏验证 6s 内收敛（该用例在阈值 0.3 的旧设计下会失败）。

## ADR-0008：零偏自愈与持久化策略

**决定**：
- 仅在 `静止 + 陀螺正常` 时累计残差，**每满 3s 静止窗口**才修正一次（避免 1ms 级别追噪声）；
- 单次修正上限 ±1°/s；修正量小于 0.002°/s 时不写 Flash；
- 两次落盘间隔 ≥60s，且**只在静止时**执行擦写；
- `calibrated` 语义（Q30.b）：本会话出现 ≥3s 静止收敛 **或** 模块侧 `0x01/0x02` 校准成功才置位；
  从 Flash 载入的零偏只作为估计起点（`Ops_Fusion_LoadBias`），**不**置 `calibrated`。

**理由**：Flash 擦页会停摆 CPU，必须用"静止 + 频率 + 变化量"三重节流；`calibrated` 不应因为"有过历史参数"就声称已标定。

**后果**：零偏随每次运行自愈，不必人工干预；上电后通常 300ms~3s 内进入 `calibrated`。

**验证**：单测 T8.2（落盘节流）、T8.3（LoadBias 不置 calibrated）。

## ADR-0009：模块侧重定基/丢帧恢复统一用 `|ΔAngle| > 90°` 规则；并主动做角度清零

**背景**：`AngleDeg` 是模块的**持续积分值**（float32）。两个问题：
1. 我们可能主动下发官方"角度清零"；别的程序也可能清零；丢帧恢复时角度可能已经大幅变化；
2. float32 在 648000° 处 ULP≈0.06°，会污染 20ms 的增量信息（增量本身只有几度）。

**决定**：
- 采样层对相邻帧算 `wrap180(ΔAngle)`，若 `|Δ| > 90°` 则判为**重定基**（不可能在 ≤20~300ms 内真实转过 90°），
  不计入航向，并置 `rebase` 标志；丢帧后的第一帧也按重定基处理；
- 融合层收到 `rebase` 时**重解 K**（`K = AngleDeg − yaw`）而非跳变，置 `GYRO_RESTORED` 位；
- 当**静止**且 `|AngleDeg| > 3000°` 时主动下发官方 `0x01/0x01` 角度清零（只清积分角、不动零偏），
  让模块的 float32 积分始终工作在最优精度区间。

**理由**：一条规则同时覆盖"我们清零"、"别人清零"、"丢帧恢复"三种情形，无需额外握手与时序假设；
`|Δ|>90°` 的判定前提（帧间不可能真转 90°）由帧周期上限 300ms 与底盘实际角速度保证。

**后果**：航向在重定基时**连续**；代价是丢帧期间的真实旋转被丢弃（设计取向：宁缺不错），由状态位提示。

**验证**：单测 T5.9（3000°→0.5° 判为重定基）、T5.10（丢帧恢复判为 rebase）、T7.4（重定基不造成航向跳变）。

## ADR-0010：线上协议 —— 固定长度 + CRC-16/MODBUS + 单一实现

**决定**：
- 上行帧一律 **26 字节**（POSE/INFO/DEBUG 同长），下行与 ACK 一律 **8 字节**；
- CRC 统一用 **CRC-16/MODBUS**（poly 0xA001，初值 0xFFFF），与 CY-Z 官方一致，
  **不采用** ops9 旧协议里的 CCITT；全模块只保留一份 `Ops_CRC16_Modbus()` 实现，
  CY-Z 协议层与底盘协议层共用，杜绝两处算法漂移；
- 下行 CRC 范围 `[2..4]`（与上行 `[2..23]` 不同），ACK 与命令帧同构（用 `0x80|cmd` 区分）。

**理由**：固定长度让接收端零缓冲、零猜测；单一 CRC 实现让"换个协议就得改两处"的风险消失。

**后果**：底盘侧只需一个 26 字节定长解析器 + 一个 8 字节定长解析器。

**验证**：单测 T3 逐字节校验三种帧的全部字段与 CRC；T1 用官方样例帧与标准校验值锚定 CRC 实现。
> 备注：`Ops_Frame_BuildAck` 曾误用上行帧的 `finish()`（CRC 覆盖长度按 26B 算）导致
> CRC 范围错误且**覆写尾字节** —— 正是 T3 用例把它抓出来的（若漏到硬件，底盘将无法解析任何 ACK）。

## ADR-0011：任务与中断划分（含"中断优先级 < 5"这条硬约束）

**决定**：
- 3 个任务：`opsSample`(1kHz, Realtime) / `opsLink`(上报+命令, AboveNormal) / `opsCyz`(链路维护 20ms, Normal)；
- 中断：TIM1/TIM2 只做硬件计数（无中断）；USART1/USART2 逐字节接收中断；
  HAL 1ms 时基 TIM4（CubeMX 生成，回调内已有 `HAL_IncTick()`）；
- **三个中断优先级都取数值 < `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY`(=5)**
  （TIM4=4、USART1=2、USART2=3）。

**理由**：
- 串口 ISR 内**不调用任何 FreeRTOS API**（只做解析与状态更新），因此可以合法地放在"内核临界区不屏蔽"的优先级区间；
- 115200 下一个字节 87us，如果 RX 中断被内核临界区屏蔽而两字节连续到达，就会触发 ORE 丢字节。
  把优先级设在 5 以下可从根上消除这一类丢字节；
- 1ms 采样做成任务（而非中断）使得所有浮点运算都在任务上下文完成，便于统计耗时（DWT）与调试。

**后果**：`HAL_UART_Transmit` 在本 HAL 版本中**不使用 `__HAL_LOCK`**（已核实源码），
因此在阻塞发送期间由中断重新挂接 `HAL_UART_Receive_IT` 不会失败；两个方向各自只有一个任务在发送，天然串行。

**验证**：语法检查 + 人工核对 HAL 源码（`stm32f1xx_hal_uart.c` 的 Transmit/Receive_IT 路径）。

## ADR-0012：命令集与 ZERO 语义 —— 不做 SET_POSE、不做 legacy 2 字节命令

**决定**：
- 只保留 10 条下行命令（见运行说明 §3.2）；
- `0x01 ZERO` 是**纯软件**重置世界原点与航向，**不触碰陀螺**（不下发官方角度清零），无需静止；
- 取消原计划的 `SET_POSE`（外部注入位姿）与旧协议的 2 字节命令；
- 标定类命令一律**转发**官方命令（0x01/0x02、0x05、0x06、0x07、0x08），不自行实现算法。

**理由**：
- ZERO 只是改变我们的坐标系原点（并按 ADR-0005 重解 K），对陀螺来说是"无操作"，因此
  不需要静止、不会打断积分、也不会丢帧；官方角度清零留给"精度维护"这一明确用途（ADR-0009）；
- 标定算法的"真值"在模块内部（它自己数圈、自己算比例因子），转发是最不易出错的做法；
- SET_POSE 会引入"外部写入 vs 内部积分"的一致性问题与新的故障模式，收益不足。

**后果**：底盘可以在任意时刻、任意姿态下 ZERO；标定命令的静止要求由模块返回 `result=0x03` 明确体现。

**验证**：单测 T8.5/T8.6（ZERO 不影响零偏与标定、REINIT 保留零偏与标定）。

## 附录 B：相对最初计划被**修改/推翻**的决定（避免后续讨论重复踩坑）

| 原计划 | 修改为 | 原因 |
|---|---|---|
| 上电发命令把 CY-Z 设为 200Hz | 不发任何未文档化命令；被动监听 + 查询模式自动判定 + 帧周期自适应 | 官方文档中不存在该命令（ADR-0004） |
| 假定陀螺 200Hz、丢帧阈值为 5 帧 | 帧周期运行期测量，超时 = 3×实测周期（25~300ms 钳位） | 同上 |
| 航向用 `AngleDeg` 增量按 tick 插值 | 速率积分（ZOH）+ 每帧绝对角慢校正 | 插值滞后在弧线工况带来约 8mm 系统误差（ADR-0005） |
| ZUPT 判据"2 脉冲/ms" | 100ms 滑窗 + 8 脉冲/窗口 | 2 脉冲/ms = 0.356 m/s，会吞掉慢速运动（ADR-0006） |
| 静止角速度阈值 0.3°/s | 0.6°/s + 残差稳定带兜底 | 否则残余零偏大于阈值时永远学不到零偏（ADR-0007） |
| SET_POSE 命令（外部注入位姿） | 取消 | 一致性与故障模式成本高于收益（ADR-0012） |
| 兼容 ops9 旧协议 2 字节命令 | 取消，只保留 8 字节定长下行 | 定长更易验证（ADR-0010、ADR-0012） |
| CRC 沿用 ops9 的 CCITT | 统一 CRC-16/MODBUS | 与 CY-Z 一致，全模块一份实现（ADR-0010） |
| 采样放在 TIM4 回调里 | 放在 1kHz RTOS 任务里 | 便于测量耗时与调试；计数由硬件保证无损（ADR-0011） |
| 上报任务与命令任务分开 | 合并为一个 `opsLink` 任务 | 上行发送天然串行化，少一个任务与一份同步（ADR-0011） |
| 任务栈按 CubeMX 默认 3072 字节堆分配 | 堆扩到 6144 | 3 个任务栈 + TCB 放不下（附录 A） |

## 附录 C：未决事项 / 需要硬件确认的 3 件事

1. **CY-Z 是否存在"接口选择"脚**：若存在，必须固定在 UART 模式，
   且**绝不能接到 PA0**（PA0 已被轮 B 脉冲占用）。官方文档未提该引脚，但硬件实物需目视确认。
2. **CY-Z 的 TX/RX 与 PB7/PB6 的对应**：必须交叉（模块 TX → PB7）。
3. **两轮滚动轴线是否过模块中心**（Q28.a）：若不过，按运行说明 §6.3 填 `OPS_WHEEL_A_X_M` / `OPS_WHEEL_B_Y_M`
   即可，代码无需改动（解耦结构已参数化）。

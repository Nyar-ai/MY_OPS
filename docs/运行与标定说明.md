# MY_OPS 全局位姿模块 — 运行与标定说明

> 模块：STM32F103C8T6 + 双路（脉冲+方向）编码器 + CY-Z(QMM01) 单轴陀螺
> 功能：解算麦轮底盘的**世界系位姿**（x, y, yaw，含连续航向），100Hz 上报给底盘 MCU
> 指标目标：**≤25mm/5m 位置误差**、**≤1°/min 静止漂移**、上报 **≥100Hz**、端到端 **≤20ms**

---

## 1. 硬件与接线

| 功能 | 引脚 | 外设 | 备注 |
|---|---|---|---|
| 轮 A 脉冲（测 y / 左右） | **PA8** | TIM1_CH1，外部时钟模式 1 | 上升沿计数 |
| 轮 A 方向 | **PA10** | GPIO 输入 | `DIRT1`，1 = 正转 |
| 轮 B 脉冲（测 x / 前后） | **PA0** | TIM2_CH1，外部时钟模式 1 | 上升沿计数 |
| 轮 B 方向 | **PA11** | GPIO 输入 | `DIRT2`，1 = 正转 |
| CY-Z 陀螺 | **PB6=TX / PB7=RX** | USART1（已开重映射），115200 8N1 | 官方推荐串口接口 |
| 底盘 MCU | **PA2=TX / PA3=RX** | USART2，115200 8N1 | 26B 上行 / 8B 下行 |
| 状态灯 | **PC13** | GPIO，低电平点亮 | 见 §2 |
| 参数存储 | Flash `0x0800FC00` | 最后 1KB 页 | 零偏/上报频率 |

> **接线检查 3 条**（错一条就会完全不工作）：
> 1. CY-Z 的 TX 必须接 **PB7**、RX 接 **PB6**（交叉）；
> 2. 若 CY-Z 存在"接口选择/模式选择"脚，必须把它固定在 **UART 模式**，
>    **绝不能接到本板 PA0**（已被轮 B 脉冲占用）；
> 3. 方向脚与脉冲脚必须来自**同一个轮子**；若发现某轮读数是乱跳的，
>    把 `OPS_DIR_SWAP` 改为 `1` 交叉配对（见 §6.1）。

## 2. 上电流程

1. `MX_GPIO/TIM1/TIM2/USART1/USART2_Init()`（CubeMX 生成）；
2. `Ops_Init()`（main.c 的 `USER CODE 2` 段）依次做：
   - **补编码器输入通道**：给 TIM1/TIM2 配置 `CC1S=01`（`TIM_ICSELECTION_DIRECTTI`）
     并设置输入滤波 `OPS_ENC_IC_FILTER`，然后 `HAL_TIM_Base_Start()` 开始计数。
     *（CubeMX 生成的 `HAL_TIM_SlaveConfigSynchro()` 只写 SMCR，不写 CC1S，
     缺少这一步计数器一个脉冲都数不到 —— 见 ADR-0002）*
   - 配置 NVIC 优先级、使能 DWT、启动两路串口逐字节中断接收；
   - 从 Flash 载入参数（无效则用默认值）；
   - `Ops_Sample_Init()` 建立编码器基准（**读-差-存**，永不写 `CNT`）。
3. `osKernelStart()` → `Ops_Tasks_Init()` 创建 3 个任务：

| 任务 | 优先级 | 周期 | 职责 |
|---|---|---|---|
| `opsSample` | Realtime(48) | 1ms | 取采样快照 + 融合一步（纯计算） |
| `opsLink` | AboveNormal(32) | 1000/report_hz | 发位姿帧、处理命令、回 ACK/INFO、零偏落盘 |
| `opsCyz` | Normal(24) | 20ms | CY-Z 链路维护（模式探测/轮询/角度清零） |

4. **CY-Z 模式自动判定**：上电后先被动监听 `OPS_CYZ_PROBE_MS`(300ms)；
   - 收到遥测 → **推流模式**，之后不再发任何查询命令；
   - 无任何帧 → **查询模式**，按 100Hz 发 `0x04` 查询，多次无响应时自动退避到 20Hz。
   模块实际帧周期会被测量并显示在 INFO 帧里（`gyro_period_ms`）。

## 3. 通信协议（底盘 ↔ 本模块）

### 3.1 上行帧（模块 → 底盘）：固定 **26 字节**

```
偏移  0   1   2     3    4 .............. 23  24  25
     AA  55  type  seq      payload(20B)      CRC16(LE)
```
CRC：**CRC-16/MODBUS**（poly 0xA001，初值 0xFFFF），范围 **[2..23]**，低字节在前。

**POSE（type=0x01）payload：**

| 偏移 | 类型 | 含义 | 单位/分辨率 |
|---:|---|---|---|
| 0 | i32 | x | mm |
| 4 | i32 | y | mm |
| 8 | i32 | yaw（连续、已 unwrap） | 0.01° |
| 12 | i16 | vx | mm/s |
| 14 | i16 | vy | mm/s |
| 16 | i16 | w | 0.01°/s |
| 18 | u16 | status | 见 §4 |

**INFO（type=0x02）payload：** fw u16 | report_hz u16 | gyro_period_ms u16 |
mode u8 | calibrated u8 | gyro_frames u32 | gyro_err u16 | uart_err u16 |
pulse_err u16 | scale_x1000 i16

**DEBUG（type=0x03，需先下发 0x09 开启）payload：** cnt_a i32 | cnt_b i32 |
angle_cdeg i32 | dps_cdeg i16 | age_ms u16 | loop_us u16 | bias_x1000 i16

### 3.2 下行命令（底盘 → 模块）：固定 **8 字节**

```
5A  A5  cmd  param  seq  CRC16(LE)  A5      CRC 范围 = [2..4]
```

| cmd | 名称 | param | 行为 |
|---:|---|---|---|
| 0x01 | ZERO | 0 | **软件**重置世界原点与航向（不触碰陀螺，无需静止） |
| 0x02 | REINIT | 0 | 清积分器并重走上电流程（保留零偏/标定），同时请求一次陀螺角度清零 |
| 0x03 | SET_REPORT_HZ | 50/100/200 | 改变上报频率（RAM 会话内生效） |
| 0x04 | CAL_BIAS | 0 | 转发 CY-Z `0x01/0x02` 零偏校准（**须静止，约 2s**） |
| 0x05 | CAL_SCALE_START | 1/2/3/6 | 转发 CY-Z `0x05` 开始比例校准（圈数） |
| 0x06 | CAL_SCALE_FINISH | 0 | 转发 CY-Z `0x06` 完成并保存比例因子（**须静止**） |
| 0x07 | CAL_CANCEL | 0 | 转发 CY-Z `0x07` 取消 |
| 0x08 | GET_INFO | 0 | 立即回一帧 INFO |
| 0x09 | SET_DEBUG | 0/1 | 开启/关闭 100ms 周期 DEBUG 帧 |
| 0x0A | GET_SCALE | 0 | 读取陀螺比例因子并回一帧 INFO |

### 3.3 ACK 帧（模块 → 底盘）：固定 **8 字节**

```
5A  A5  0x80|cmd  result  seq  CRC16(LE)  A5
```
`result`：0x00 成功 / 0x02 参数错 / 0x03 条件不满足（如未静止）/ 0x04 链路不可用。

## 4. status 状态位（u16）

| 位 | 名称 | 含义 |
|---:|---|---|
| 0 | VALID | 位姿数据有效（正常运行恒为 1） |
| 1 | CALIBRATED | 零偏已标定：本会话出现 ≥3s 静止收敛，或模块侧 `0x04` 校准成功 |
| 2 | STATIC | 静止检测生效中（此期间位置与航向被冻结） |
| 3 | GYRO_OK | 陀螺帧正常（未超过 3×实测帧周期） |
| 4 | OVERRUN | 最近 5s 内出现过链路异常（串口/陀螺） |
| 5 | GYRO_RESTORED | 陀螺刚恢复/检测到模块侧角度重定基，航向已重新对齐（保持 300ms） |
| 6 | GEOM_DIAG | 快速旋转（>30°/s）**且**轮速持续非零 >200ms：可能偏心/打滑，或正在做弧线运动 |
| 7+ | — | 保留 |

> 位 3 为 0 时：**航向被冻结（不清零）**，位置仍由轮子正常推进；恢复后置位 5。

## 5. 可调参数（全部在 `ops_config.h`）

| 宏 | 默认 | 含义 |
|---|---|---|
| `OPS_ENCODER_PULSE_PER_REV` | 1024 | 单轮每转脉冲数 |
| `OPS_WHEEL_RADIUS_M` | 0.029 | 轮半径 m（**必标，见 §6.2**） |
| `OPS_DIR_QUADRANT` | 2 | 方向象限 1=(+,+) 2=(−,+) 3=(−,−) 4=(+,−)，出厂与 ops9 一致 |
| `OPS_DIR_SWAP` | 0 | 方向脚配对是否交叉 |
| `OPS_WHEEL_A_X_M` / `OPS_WHEEL_B_Y_M` | 0 | 轮轴线偏心（**现场确认为 0**，否则填实测值即可自动解耦） |
| `OPS_SAMPLE_TICK_MS` | 1 | 采样节拍 |
| `OPS_REPORT_HZ` | 100 | 默认上报频率（可用 0x03 改） |
| `OPS_ZUPT_GYRO_DPS` | 0.6 | 静止判据角速度阈值（**必须大于最坏残余零偏**） |
| `OPS_ZUPT_WIN_MS` / `OPS_ZUPT_PULSES_PER_WIN` | 100 / 8 | 运动判据滑窗与其脉冲阈值（8 脉冲/100ms ≈ 0.014 m/s） |
| `OPS_ZUPT_HOLD_MS` | 200 | 连续静止多久才冻结 |
| `OPS_BIAS_MIN_STATIC_MS` | 3000 | 零偏自愈的静止窗口长度 |
| `OPS_BIAS_STABLE_BAND_DPS` | 0.05 | 残差稳定带（打破"零偏>阈值就永远学不到零偏"的死锁） |
| `OPS_BIAS_WRITE_DELTA_DPS` / `_MIN_INTERVAL_MS` | 0.002 / 60000 | Flash 落盘节流 |
| `OPS_GYRO_RESYNC_ALPHA` | 0.05 | 每帧绝对角慢校正系数（@50Hz ≈ 0.4s 时间常数） |
| `OPS_CYZ_REBASE_JUMP_DEG` | 90 | 单帧角度跳变超过此值判为模块重定基（非真实运动） |
| `OPS_CYZ_REBASE_TRIGGER_DEG` | 3000 | 静止且模块积分角超过此值时自动发一次角度清零 |
| `OPS_CYZ_TIMEOUT_MIN/MAX_MS` | 25 / 300 | 丢帧超时自适应范围（= 3×实测帧周期） |
| `OPS_GEOM_DIAG_*` | 30 / 200 / 50 | 几何/打滑诊断阈值 |
| `OPS_ENC_IC_FILTER` | 0x8 | 编码器输入滤波（fDTS/8 取 6 样 ≈0.67us，不吞真实脉冲） |

## 6. 必做的三项现场校验

> 校验手段统一为：先下发 `0x09 param=1` 打开 DEBUG 帧（能直接看到 `cnt_a/cnt_b`），
> 或用 `tools/pose_plot.py` 看 POSE 帧。

### 6.1 方向象限（决定"正负号"，1 分钟）

1. `0x01 ZERO` 归零；
2. 手推整车**向前**移动约 1m：`cnt_b` 应增加、`x_mm` 应为 **+1000 左右**、`y_mm` 接近 0；
3. 手推整车**向左**移动约 1m：`cnt_a` 应增加、`y_mm` 应为 **+1000 左右**。

- 若某一轴符号相反 → 修改 `OPS_DIR_QUADRANT`：1=(+,+) 2=(−,+) 3=(−,−) 4=(+,−)；
  当前默认 2 表示"轮 A 取反、轮 B 取正"。
- 若某轮 `cnt` 乱跳 → 方向脚接到了另一个轮子：把 `OPS_DIR_SWAP` 改成 `1`。

**灵敏度参考**：直线 1m 应产生 `1 / 0.00017793 ≈ 5620` 个脉冲。
偏差超过 2% 说明机械/编码器有问题（脉冲数丢失或轮打滑）。

### 6.2 每米脉冲数（决定 25mm/5m 能否达成，**必须做**）

> 指标 25mm/5m = **0.5%**。轮半径 29mm 的 0.5% 只有 **0.145mm** ——
> 用标称轮径不可能守住这个预算，必须实测标定。

1. `0x01 ZERO`；
2. 沿直线**精确**推车 ≥3m（越长约准，用卷尺量真实距离 `L`）；
3. 读 DEBUG 帧的 `cnt_b`（取推车前后差值 `N`），读 POSE 的 `x_mm`；
4. 计算并改宏：

```
新 M_PER_PULSE = L / N                       (m/脉冲)
新 OPS_WHEEL_RADIUS_M = L * 1024 / (2π * N)  (m)
```

示例：推 `L = 5.000m` 得 `N = 27800` 脉冲 →
`M_PER_PULSE = 0.00017986 m` → `OPS_WHEEL_RADIUS_M = 0.029318`（把宏从 0.029 改为 0.029318）。

改完后复测：再推 5m，`x_mm` 与卷尺值之差应 ≤ 数毫米量级。

> 两轮轮径若不一致：本模块只用两只轮子测两个正交方向，不做左右轮对称校正；
> 用"两轮各自标定"即可，残余不一致会表现为航向漂移，由陀螺通道承担。

### 6.3 几何偏心确认（Q28.a 的现场验证，10 分钟）

让底盘**原地自转 90°**（不做平移），观察 POSE 的 `x/y`：

- `|Δx|、|Δy|` 都 < 5mm 且与旋转角无强相关 → 偏心 ≈ 0 ✔
  保持 `OPS_WHEEL_A_X_M = OPS_WHEEL_B_Y_M = 0`；
- 若随旋转**单调**漂移 → 存在偏心，实测后填宏（无需改代码逻辑）：

```
Δθ = 旋转角(rad)
OPS_WHEEL_B_Y_M ≈ Δx / Δθ      (轮B 的 y 偏心)
OPS_WHEEL_A_X_M ≈ −Δy / Δθ     (轮A 的 x 偏心)
```

例如自转 90°(=1.5708 rad) 后 Δx = +12mm → `OPS_WHEEL_B_Y_M ≈ 0.0076 m`。

> 纯旋转工况下 `status.GEOM_DIAG`(bit6) 也会被点亮，这是**设计行为**：它表示
> "快速旋转且轮子在持续转动"，既可能是偏心/打滑，也可能是正常的弧线运动，需人工区分。

## 7. 完整标定流程（按顺序执行）

| 步骤 | 操作 | 期望结果 |
|---:|---|---|
| 1 | §6.1 方向象限 | 推车方向与 x/y 符号一致 |
| 2 | §6.2 每米脉冲 | 5m 直线位置误差 ≤ 数毫米（标定残差） |
| 3 | §6.3 几何偏心 | 原地自转不产生位置漂移 |
| 4 | 陀螺零偏：整车完全静止，下发 `0x04` | 收 ACK `result=0x00`；若 `0x01` 表示未静止，重新静止再试 |
| 5 | 保持静止 ≥5s（模块自校准 2s + 本模块软件残差 3s 收敛） | `status.CALIBRATED`(bit1) 置位；零偏随后自动写入 Flash（60s 节流） |
| 6 | 陀螺比例：先静止，下发 `0x05 param=3`，同向匀速自转 **3 整圈**，停稳后下发 `0x06` | 均收 ACK `result=0`；再进行步骤 7 |
| 7 | 下发 `0x0A` 读回比例因子 | INFO 帧 `scale_x1000` ≈ 1000（偏离越大说明修正越多） |
| 8 | 复检：`0x01 ZERO` → 原地转 360° → 读 yaw | `yaw` 回到 ≈0（±1°） |
| 9 | 复检：`0x01 ZERO` → 直推 5m | `x_mm` 与卷尺差 ≤25mm |

> 步骤 4~7 都是**转发官方命令**，命令表与静止要求全部来自官方《CY-Z协议.md》，
> 本模块不发明任何新命令。角度清零（`0x01/0x01`）不会被使用：
> 本模块的 `0x01 ZERO` 是纯软件重置，不需要静止，也不会打断陀螺积分。

## 8. 验收测试

### A. 静止漂移 ≤ 1°/min（10 分钟）

1. 整车静置，`0x09 param=0`（关调试帧）以免干扰；
2. 用串口助手以二进制保存 10 分钟数据 → `python tools/pose_plot.py cap.bin --csv t.csv`；
3. 判定：
   - `STATIC` 位占比应 > 95%（说明 ZUPT 正常工作）；
   - `yaw` 首尾差 < 10°（=1°/min × 10min）。
   - **更强判据**：`STATIC` 位为 1 期间 `yaw` 应**逐帧完全不变**（设计上被硬冻结），
     若发现静止期间 yaw 仍在变，说明有振动/被拖动触发了运动判据解除。

### B. 5m 直线 ≤ 25mm（核心指标）

1. `0x01 ZERO`；
2. 直线行驶/推车 5m（同一方向重复 3 次，每次重新 ZERO）；
3. 终点用卷尺量真实位移 `L_true`，与 POSE 的 `x_mm` 比较；
4. 判定 `|x_mm/1000 − L_true| ≤ 0.025 m`。

> 该项误差 ≈ 每米脉冲标定残差 × 5m，所以 **§6.2 的标定质量直接决定验收结果**。

### C. 100Hz 与延迟 ≤ 20ms

1. 帧间隔：从抓包中统计相邻 POSE 帧时间差，应 ≈ 10ms（100Hz）；
2. 实际计算负载：开调试帧看 `loop_us`，1ms 任务的单次耗时预期 **20~60us**（<5% CPU）；
3. 端到端延迟预算（典型）：

| 环节 | 延迟 |
|---|---|
| 陀螺采样+上报（默认 50Hz） | 0 ~ 20ms（速率积分使积分本身无额外滞后） |
| 1ms 任务采样与融合 | ≤1ms |
| 上报任务调度 | ≤10ms（100Hz） |
| 26 字节 @115200 发送 | 2.3ms |
| **合计** | **典型 12~15ms，最坏 <20ms** |

### D. 回环（参考项，弧线工况）

走 2m×2m 方形回到起点，终点位置误差 ≤50mm（弧线工况下航向误差×位移占主导）。

## 9. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| DEBUG 帧 `cnt_a/cnt_b` 始终不变 | 编码器未供电/未接地；PA8/PA0 接错；**CC1S 未配置**（若有人改回 `tim.c` 原样） | 确认 `Ops_Hw_Init()` 被调用（`Ops_Init()` 内第一件事） |
| `cnt` 变化但符号相反 | 方向象限不符 | §6.1 改 `OPS_DIR_QUADRANT` |
| `cnt` 每次读数跳很大 | 方向脚接错轮 / 接触不良 / 强干扰 | 改 `OPS_DIR_SWAP`；检查屏蔽与共地 |
| 完全收不到 POSE 帧 | 波特率不是 115200；PA2/PA3 反接；底盘侧 CRC 不是 MODBUS | 用示波器看 PA2 是否有数据 |
| 帧头对但 CRC 错 | 电平不匹配/长线干扰/未共地 | 缩短线缆、加共地、降波特率试 |
| `GYRO_OK` 长期为 0 | PB6/PB7 反接、模块未供电、模块不在 UART 模式、波特率 | 用官方示例程序单独测模块 |
| `GYRO_RESTORED` 频繁置位 | 链路干扰丢帧，或模块被反复清零 | 查供电与线缆；确认没有别的程序在发清零命令 |
| yaw 持续缓慢漂移且 `STATIC` 不置位 | 机体微振/轮子被拖动 >8 脉冲/100ms | 适当提高 `OPS_ZUPT_PULSES_PER_WIN`（如 12） |
| `CALIBRATED` 一直为 0 | 没有出现过连续 ≥3s 静止；或模块未回 ACK | 静置 5s 观察；查 CY-Z 链路 |
| 自转时位置漂移 | 偏心未标定（§6.3）或轮径错（§6.2） | 重新标定 |
| Flash 参数丢失/异常 | 程序越界占用了末页 | 检查 `.map` 最大地址 < `0x0800FC00` |

## 10. 已知限制与精度预算（如实说明）

| # | 限制 | 量级/影响 | 缓解手段 |
|---:|---|---|---|
| 1 | 定向轮（脉冲+方向）在 1ms 采样下，**方向翻转窗口内的符号误差** | 每次翻转 ≤ 窗口内脉冲数（≤6 个 = 1.1mm） | ZUPT 100ms 判据 + 静止冻结，使其不累积 |
| 2 | 陀螺速率通道的固有滞后 = 模块帧周期（默认 50Hz = 20ms） | 稳态航向误差 ≈ `比例误差 × ω × T_frame / α`；1% 比例误差 @90°/s → **0.36°**（单测 T7.2 覆盖） | 速率积分（零阶保持，本身不引入额外滞后）+ 每帧慢校正 α=0.05 |
| 3 | ZUPT 生效需要 200~300ms | 期间残余零偏带来**一次性** ≤0.12° 航向偏移（0.4°/s × 0.3s），不累积 | 降低零偏（模块 0x04 校准）+ 软件自愈收敛 |
| 4 | 陀螺丢帧期间航向被冻结（不清零） | 若丢帧时真实发生了旋转，恢复后会有**已知的航向缺口** | 置 `GYRO_RESTORED` 位提示底盘；设计取向是"宁缺不错" |
| 5 | Flash 页擦除 20~40ms 会让 CPU 停摆 | 期间：轮脉冲由硬件计数仍无损；陀螺可能丢 1~N 帧并按"恢复"处理 | 只在**静止**时落盘 + 60s 节流 + 变化阈值 |
| 6 | 弧线（边转边走）工况误差大于直线 | 误差 ≈ 航向误差 × 位移；25mm/5m 指标针对"直线 + 原地转向" | 验收按 §8.B 与 §8.D 分别判定（直线 25mm / 回环 50mm） |
| 7 | 上报为阻塞发送（26B = 2.26ms，在低优先级任务内） | 不占用 1ms 任务；最坏占用 100Hz 周期的 23% | 需要多路广播/DMA 时可改用 DMA（`stm32f1xx_hal_dma.c` 已在编译列表） |
| 8 | 陀螺模块实际上报速率由模块固件决定（官方枚举仅 50/20/10Hz，且**没有**设置速率的文档命令） | 无法主动提速到 200Hz | 运行期测量帧周期并自适应超时；上报给底盘仍稳定 100Hz |
| 9 | `AngleDeg` 是持续积分值（float32） | 长时间运行后精度退化（648000° 处 ULP≈0.06°，会污染 20ms 增量） | 静止且 \|角度\|>3000° 时自动下发官方角度清零，并用 `\|Δ\|>90°` 规则重新对齐，航向无跳变 |
| 10 | 官方 SDK 的 `CYZ_StreamParser` 缓冲仅 16 字节，而 boot 帧帧长最大 271 | 一旦进入 Bootloader 流程会**越界写** | 本模块不移植 boot 帧、永不进入 boot；解析器另有硬性边界检查（单测 T2.4 覆盖） |
